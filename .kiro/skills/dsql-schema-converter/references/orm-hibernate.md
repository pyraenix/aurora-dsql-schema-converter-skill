## 1. Dependencies

```xml
<!-- pom.xml -->
<dependencies>
    <!-- Aurora DSQL Hibernate dialect -->
    <dependency>
        <groupId>software.amazon.dsql</groupId>
        <artifactId>aurora-dsql-hibernate</artifactId>
        <version>LATEST</version>
    </dependency>

    <!-- PostgreSQL JDBC driver -->
    <dependency>
        <groupId>org.postgresql</groupId>
        <artifactId>postgresql</artifactId>
    </dependency>

    <!-- AWS SDK for token generation -->
    <dependency>
        <groupId>software.amazon.awssdk</groupId>
        <artifactId>dsql</artifactId>
    </dependency>

    <!-- HikariCP connection pool -->
    <dependency>
        <groupId>com.zaxxer</groupId>
        <artifactId>HikariCP</artifactId>
    </dependency>
</dependencies>
```

## 2. Connection Configuration

### Spring Boot (application.yml)

```yaml
spring:
  datasource:
    url: jdbc:postgresql://<cluster-id>.<region>.dsql.amazonaws.com:5432/postgres?sslmode=require
    # No username/password — IAM token generated by adapter
    hikari:
      maximum-pool-size: 10
      max-lifetime: 1800000    # 30 min (below DSQL's 1-hour timeout)
      connection-timeout: 5000
  jpa:
    database-platform: software.amazon.dsql.hibernate.AuroraDsqlDialect
    hibernate:
      ddl-auto: none           # NEVER use auto DDL with DSQL
    properties:
      hibernate:
        jdbc:
          batch_size: 100      # Batch inserts (stay under 3000 row limit)
```

### IAM Token Generation (HikariCP DataSource)

```java
import software.amazon.awssdk.services.dsql.DsqlUtilities;
import com.zaxxer.hikari.HikariConfig;
import com.zaxxer.hikari.HikariDataSource;

public class DsqlDataSourceConfig {

    public HikariDataSource createDataSource(String clusterEndpoint, String region) {
        HikariConfig config = new HikariConfig();
        config.setJdbcUrl("jdbc:postgresql://" + clusterEndpoint + ":5432/postgres?sslmode=require");
        config.setMaximumPoolSize(10);
        config.setMaxLifetime(1800000); // 30 minutes

        // Generate fresh IAM token for each connection
        DsqlUtilities utilities = DsqlUtilities.builder()
            .region(Region.of(region))
            .build();

        config.setUsername("admin");
        config.setPassword(utilities.generateDbConnectAdminAuthToken(builder ->
            builder.hostname(clusterEndpoint)
        ));

        return new HikariDataSource(config);
    }
}
```

**Important:** IAM tokens expire after 15 minutes. HikariCP's `maxLifetime` should be set below this, or use a token-refreshing connection provider.

## 3. Entity Changes

### Use UUID Primary Keys

```java
import jakarta.persistence.*;
import java.util.UUID;

@MappedSuperclass
public abstract class BaseEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.UUID)
    private UUID id;

    // getters/setters
}
```

### Remove @ManyToOne / @OneToMany FK Relationships

```java
// BAD: Hibernate will try to create FK constraint
@Entity
public class Ticket {
    @ManyToOne
    @JoinColumn(name = "org_id")
    private Organization org;  // Creates FK
}

// GOOD: Plain column + application validation
@Entity
@Table(name = "tickets")
public class Ticket extends BaseEntity {

    @Column(name = "org_id", nullable = false)
    private Long orgId;

    @Column(name = "reporter_id", nullable = false)
    private UUID reporterId;

    @Column(name = "title", nullable = false, length = 500)
    private String title;

    @Column(name = "priority", length = 20)
    private String priority;  // ENUM → varchar with CHECK

    @Column(name = "metadata", columnDefinition = "json")
    private String metadata;  // JSON stored as json type

    @Column(name = "created_at")
    private Instant createdAt;
}
```

### JSON Columns

```java
// Option 1: Store as String, map to json column
@Column(name = "settings", columnDefinition = "json")
private String settings;

// Option 2: Use Hibernate Types library for automatic serialization
@Type(JsonType.class)
@Column(name = "settings", columnDefinition = "json")
private Map<String, Object> settings;
```

### Avoid Unsupported Annotations

| Hibernate Annotation | DSQL Behavior | Alternative |
|---|---|---|
| `@ManyToOne` / `@OneToMany` | FK constraint fails | Plain column + service validation |
| `@ManyToMany` (join table) | FK constraints fail | Manual join table, no FKs |
| `@GeneratedValue(SEQUENCE)` | Works if CACHE 1 or ≥65536 | Specify `allocationSize` carefully |
| `@GeneratedValue(IDENTITY)` | Works (GENERATED BY DEFAULT) | Preferred for auto-increment |
| `@Enumerated(EnumType.STRING)` | Works (stored as varchar) | ✅ No change needed |
| `@Temporal` | Works | ✅ No change needed |

## 4. Disable DDL Auto-Generation

**Never use `hibernate.ddl-auto = create` or `update` with DSQL.**

DSQL requires one DDL per transaction. Hibernate's auto-DDL batches multiple statements.

```yaml
# application.yml
spring:
  jpa:
    hibernate:
      ddl-auto: none    # Always 'none' for DSQL
```

Use Liquibase or Flyway with custom changesets that execute one DDL per changeset:

```xml
<!-- Liquibase changeset — one DDL per changeset -->
<changeSet id="1" author="dev">
    <createTable tableName="organizations">
        <column name="id" type="bigint" autoIncrement="true">
            <constraints primaryKey="true"/>
        </column>
        <column name="name" type="varchar(200)">
            <constraints nullable="false" unique="true"/>
        </column>
    </createTable>
</changeSet>

<!-- Separate changeset for index -->
<changeSet id="2" author="dev">
    <sql>CREATE INDEX ASYNC idx_org_name ON organizations (name)</sql>
</changeSet>
```

## 5. OCC Retry with Spring

### Spring Retry

```xml
<dependency>
    <groupId>org.springframework.retry</groupId>
    <artifactId>spring-retry</artifactId>
</dependency>
```

```java
import org.springframework.retry.annotation.Retryable;
import org.springframework.retry.annotation.Backoff;
import org.springframework.transaction.annotation.Transactional;
import org.hibernate.exception.LockAcquisitionException;

@Service
public class TicketService {

    @Retryable(
        retryFor = {LockAcquisitionException.class},  // Hibernate wraps 40001 as this
        maxAttempts = 5,
        backoff = @Backoff(delay = 50, multiplier = 2, maxDelay = 5000)
    )
    @Transactional
    public Ticket createTicket(Long orgId, UUID reporterId, String title) {
        // Validate FKs
        if (!organizationRepository.existsById(orgId)) {
            throw new EntityNotFoundException("Organization not found: " + orgId);
        }
        if (!userRepository.existsById(reporterId)) {
            throw new EntityNotFoundException("Reporter not found: " + reporterId);
        }

        Ticket ticket = new Ticket();
        ticket.setOrgId(orgId);
        ticket.setReporterId(reporterId);
        ticket.setTitle(title);
        ticket.setCreatedAt(Instant.now());
        return ticketRepository.save(ticket);
    }
}
```

### Manual Retry (without Spring Retry)

```java
public <T> T executeWithRetry(Supplier<T> operation, int maxRetries) {
    for (int attempt = 0; attempt < maxRetries; attempt++) {
        try {
            return operation.get();
        } catch (Exception e) {
            if (isOccConflict(e) && attempt < maxRetries - 1) {
                long delay = Math.min(50 * (long) Math.pow(2, attempt) + ThreadLocalRandom.current().nextLong(50), 5000);
                Thread.sleep(delay);
            } else {
                throw e;
            }
        }
    }
    throw new RuntimeException("Max retries exceeded");
}

private boolean isOccConflict(Exception e) {
    Throwable cause = e;
    while (cause != null) {
        if (cause instanceof PSQLException psql && "40001".equals(psql.getSQLState())) {
            return true;
        }
        cause = cause.getCause();
    }
    return false;
}
```

## 6. Batch Operations

Stay under DSQL's 3,000 row limit:

```java
@Transactional
public void bulkInsert(List<Ticket> tickets) {
    // Batch in groups of 500 (well under 3000 limit)
    List<List<Ticket>> batches = Lists.partition(tickets, 500);
    for (List<Ticket> batch : batches) {
        ticketRepository.saveAll(batch);
        entityManager.flush();
        entityManager.clear();
    }
}
```

**Important:** Each `saveAll` + `flush` is one transaction. If you need multiple batches, each must be a separate transaction (separate `@Transactional` call).

## 7. Sequence Configuration

```java
@Entity
public class Invoice extends BaseEntity {

    // Use explicit sequence with DSQL-compatible CACHE
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "invoice_seq")
    @SequenceGenerator(
        name = "invoice_seq",
        sequenceName = "invoice_seq",
        allocationSize = 1  // Must match CACHE 1 or set to 65536
    )
    private Long id;
}
```

**Critical:** Hibernate's default `allocationSize = 50` won't work with DSQL's CACHE 1. Set `allocationSize = 1` for CACHE 1 sequences, or `allocationSize = 65536` for high-throughput.

- [ ] Add service-layer FK validation

- [ ] Batch writes to ≤500 rows per transaction
- [ ] Use Liquibase/Flyway with one DDL per changeset
